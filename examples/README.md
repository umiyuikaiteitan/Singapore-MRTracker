# Example output

These pages are generated from the miniature test feed in
`crates/mrt-gtfs/tests/fixtures/mini`, so they are small enough to
read and to diff, and they exercise every awkward case the pipeline
handles: two platforms per station, a short turn, an exact headway
block, a non-exact one, a trip with missing intermediate times, a
pass-through call, a branch that no single station axis can hold with
the main line, and a trip that runs past midnight.

| File | What it shows |
|------|---------------|
| `timetable-woodlands.html` | A station departure timetable: one panel per platform and direction, service-day hour ordering, computed times marked, first and last departure marked. |
| `diagram-tel.html` | A train diagram with its page: filters, pan and zoom, hover details, and a call table for every run. |
| `diagram-tel.svg` | The same drawing as a standalone file. |
| `manifest.json` | The generation manifest of the timetable run. |
| `baseline/` | Rendered screenshots for `scripts/visual-regression.sh`. |

`cargo test -p mrt-publication-html --test visual_tests` regenerates
the three pages, so they never drift from the renderer. The manifest
is generated by hand, because it records a generation time and would
otherwise change on every run:

```sh
cargo run -p mrt-schedule-cli -- timetable \
  --feed crates/mrt-gtfs/tests/fixtures/mini \
  --station TE2 --line TE --date 2025-05-05 \
  --config config/singapore.yaml \
  --out examples/timetable-woodlands.html \
  --manifest examples/manifest.json
```

Open a page from the file system. It needs no server and makes no
network request of any kind.
